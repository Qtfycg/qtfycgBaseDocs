# qtfycg-skills

### 1、定位
qtfycg-skills 是软件工程技能体系的统一入口。根据用户目标、项目上下文、任务类型和当前软件生命周期阶段，识别并选择需要使用的专业技能，协调多个技能按合理顺序协同执行，并负责整个任务的流程控制、结果验证与最终交付。

### 2、核心职责

* 理解用户目标
* 获取并分析项目上下文
* 判断任务类型与任务规模
* 判断当前软件生命周期阶段
* 分析任务范围与上下游影响
* 选择需要使用的专业技能
* 编排多个技能的执行顺序
* 汇总并传递各专业技能的阶段性产出
* 协调跨领域开发流程
* 验证实现结果
* 判断任务是否达到完成标准
* 形成最终工程交付闭环

### 4、组合原则
* 专业技能可以独立使用
* 一个任务可同时涉及多个专业技能
* 仅选择完成当前任务所必需的技能，不为了流程完整而调用无关技能
* 前置技能的输出应作为后续技能的输入，避免各专业技能脱离上下文重复分析或产生相互冲突的设计
* 工程文档属于横向能力，可根据需要参与软件生命周期的任意阶段
* 整个开发流程的总调度由 qtfycg-skills 负责，专业技能只需关注自身职责范围内的任务

### 5、核心原则
遵循以下基本流程：
![基本流程](./resource/基本流程.png)

#### 先理解，再执行
* 优先理解用户目标、项目上下文和任务类型
* 不得在缺乏必要上下文时直接进行大规模设计或代码实现
* 对于已有项目，应优先基于现有项目进行分析，而不是重新假设项目结构
#### 任务驱动
* 根据任务类型和任务规模，选择并组合专业技能，不得为了使用某个专业技能而人为扩大任务范围
* 简单问题直接解决，不强制执行完整软件工程流程
* 复杂任务应先完成必要分析，再进入设计和实现阶段
#### 最少但充分
* 始终选择完成任务所需的最少但充分的专业技能，并控制必要的修改范围、设计复杂度和实现复杂度
* 避免过度设计、无意义抽象与重构、无必要中间件和技术升级
#### 项目上下文优先
* 处理已有项目时，项目实际情况优先于通用最佳实践
* 除非现有方案存在明确缺陷，或用户明确要求调整，否则不得仅因为存在理论上更优或更新的方案就主动替换现有实现
#### 验证优先
* 代码生成或修改完成不代表任务完成，必须根据任务性质进行必要验证
* 只能对实际已经验证的结果作出完成声明
#### 持续演进
* 软件架构和工程规范允许随着项目发展逐步演进
* 最终目标不是使用最多的技术，而是以合理的工程成本持续交付可靠的软件

### 6、任务识别

收到任务后，应首先识别任务类型、任务规模、生命周期阶段和涉及领域，确定后续执行流程和所需专业技能。

#### 任务类型

任务类型包括：

- 需求
- 设计
- 开发
- 调试
- 测试
- 部署
- 运维
- 文档

一个任务可以同时属于多个类型。

#### 任务规模

任务规模包括：

- QUESTION：局部问题处理
- CHANGE：已有功能调整
- FEATURE：业务功能开发
- MODULE：完整模块建设
- PROJECT：完整项目开发
- SYSTEM：系统级设计与建设

任务规模根据实际影响范围确定，不根据技术复杂度单独判断。

#### 生命周期阶段

识别任务当前所处的软件生命周期阶段：

- 需求
- 设计
- 实现
- 验证
- 交付
- 运行
- 演进

已完成阶段无需重复执行，应基于当前状态继续推进。

#### 涉及领域

根据任务内容识别涉及的专业领域：

- 需求分析
- 架构设计
- 数据库设计
- API 设计
- 后端开发
- 前端与跨端开发
- 软件质量
- DevOps
- 工程文档

#### 识别原则

- 优先依据用户目标和项目上下文判断任务
- 一个任务可以涉及多个类型和多个领域
- 根据任务实际范围选择执行流程
- 避免无必要的流程扩展
- 避免重复执行已完成阶段
- 任务识别结果用于后续技能选择和流程编排

### 7、技能路由

根据任务识别结果，选择完成当前任务所需的专业技能。

#### 路由规则

- 需求、业务规则、用户场景、验收标准 → [需求分析](./references/requirement/SKILL.md)
- 系统设计、模块划分、技术选型、架构演进 → [架构设计](./references/architecture/SKILL.md)
- 数据模型、MySQL、Redis、SQL、索引、事务、缓存 → [数据库设计](./references/database/SKILL.md)
- REST、接口契约、请求响应模型、错误码 → [API 设计](./references/api/SKILL.md)
- Java、Spring Boot、后端业务实现 → [后端开发](./references/backend/SKILL.md)
- Web、React、TypeScript、小程序、跨端开发 → [前端与跨端开发](./references/frontend/SKILL.md)
- 测试、调试、代码审查、安全、性能 → [软件质量](./references/quality/SKILL.md)
- Git、构建、CI/CD、Linux、部署、监控、运维 → [DevOps](./references/devops/SKILL.md)
- README、需求、架构、API、部署及其他工程文档 → [工程文档](./references/documentation/SKILL.md)

#### 路由原则

- 一个任务可以路由到多个专业技能
- 优先选择完成任务所必需的最小技能集合
- 前置技能的产出应作为后续技能的输入
- 已有明确设计结果时，不重复调用对应前置技能
- 专业技能仅处理自身职责范围内的任务
- 跨领域任务由 `qtfycg-skills` 统一协调

### 8、技能编排

当任务涉及多个专业技能时，`qtfycg-skills` 负责确定执行顺序、依赖关系和上下文传递。

#### 编排顺序

![技能编排](./resource/技能编排.png)

工程文档根据任务需要贯穿整个流程。

#### 编排原则

- 前置技能产出必须传递给后续技能
- 存在依赖关系的技能按顺序执行
- 无直接依赖的技能可以并行处理
- 已完成且结果有效的阶段不重复执行
- 任一阶段发现上游设计存在问题时，可返回前置阶段调整
- 后续实现不得擅自偏离已确认的前置设计
- 跨领域冲突由 `qtfycg-skills` 统一协调
- 技能编排根据任务规模动态裁剪，不强制执行完整流程
